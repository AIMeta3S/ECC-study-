# 构建与修复

以最小、安全的改动增量修复构建和类型错误。

## 第 1 步：检测构建系统

识别项目的构建工具并运行构建：

| 指示符 | 构建命令 |
|-----------|---------------|
| `package.json` 含 `build` 脚本 | `npm run build` 或 `pnpm build` |
| `tsconfig.json`（仅 TypeScript） | `npx tsc --noEmit` |
| `Cargo.toml` | `cargo build 2>&1` |
| `pom.xml` | `mvn compile` |
| `build.gradle` | `./gradlew compileJava` |
| `go.mod` | `go build ./...` |
| `pyproject.toml` | `python -m compileall -q .` 或 `mypy .` |

## 第 2 步：解析并分组错误

1. 运行构建命令并捕获 stderr
2. 按文件路径分组错误
3. 按依赖顺序排序（先修复 import/类型错误，再修复逻辑错误）
4. 统计错误总数用于进度跟踪

## 第 3 步：修复循环（每次一个错误）

对每个错误：

1. **读取文件** — 使用 Read 工具查看错误上下文（错误前后 10 行）
2. **诊断** — 识别根本原因（缺失 import、类型不正确、语法错误）
3. **最小化修复** — 使用 Edit 工具做出能解决该错误的最小改动
4. **重新运行构建** — 验证该错误已消除且未引入新错误
5. **处理下一个** — 继续处理剩余错误

## 第 4 步：防护机制

出现以下情况时停止并询问用户：
- 修复**引入的错误多于解决的错误**
- **同一错误尝试 3 次后仍然存在**（可能是更深层的问题）
- 修复需要**架构层面的改动**（不只是构建修复）
- 构建错误源于**缺失依赖**（需要 `npm install`、`cargo add` 等）

## 第 5 步：总结

展示结果：
- 已修复的错误（附文件路径）
- 剩余错误（如有）
- 新引入的错误（应为零）
- 针对未解决问题的建议后续步骤

## 恢复策略

| 情况 | 操作 |
|-----------|--------|
| 缺失 module/import | 检查包是否已安装；建议安装命令 |
| 类型不匹配 | 读取两边的类型定义；修复较窄的类型 |
| 循环依赖 | 通过 import 图识别循环；建议抽取 |
| 版本冲突 | 检查 `package.json` / `Cargo.toml` 的版本约束 |
| 构建工具配置错误 | 读取配置文件；与可用的默认配置对比 |

为安全起见，每次只修复一个错误。优先采用最小 diff，而非 refactor。
