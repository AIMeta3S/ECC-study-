# Content Engine

构建平台原生内容，不要把作者真实的 voice 抹平成平台式的低质内容。

## 何时激活

- 撰写 X post 或 thread
- 起草 LinkedIn post 或发布更新
- 为短视频或 YouTube 解释类视频编写脚本
- 将文章、podcast、demo、文档或内部笔记转化为公开内容
- 围绕某个产品、洞察或叙事，构建发布序列或持续的内容系统

## 不可妥协项

1. 从源素材出发，而不是套用通用的 post 模板。
2. 针对平台适配格式，而不是改变人设。
3. 一条 post 应承载一个真实的观点。
4. 具体胜过形容词。
5. 除非用户明确要求，否则不要使用互动诱饵。

## 源素材优先工作流

在动笔前，先识别源素材集合：
- 已发布的文章
- 笔记或内部备忘录
- 产品 demo
- 文档或 changelog
- transcript
- 截图
- 同一作者此前的 post

如果用户需要特定的 voice，先从真实示例构建 voice profile，再开始写作。
当 voice 一致性涉及不止一个产出物时，使用 `brand-voice` 作为标准工作流。

## Voice 处理

`brand-voice` 是标准的 voice 层。

在以下情况先运行它：

- 存在多个下游产出物
- 用户明确关注写作风格
- 内容涉及发布、对外触达或对声誉敏感

在这里复用产出的 `VOICE PROFILE`，而不是重新构建第二个 voice 模型。
如果用户明确需要 Affaan / ECC 的 voice，仍要把 `brand-voice` 视为唯一事实来源，并向其提供可用的最佳实时或源衍生素材。

## 严格禁止项

删除并重写以下任何内容：
- "In today's rapidly evolving landscape"
- "game-changer"、"revolutionary"、"cutting-edge"
- "here's why this matters"（除非后面紧跟具体内容）
- 以 LinkedIn 风格的问题结尾，只为骗取回复
- 在 LinkedIn 上强行装作随意
- 源素材中不存在的虚假互动填充内容

## 平台适配规则

### X

- 用最强的观点、成果或张力开场
- 如果源 voice 是凝练的，就保持凝练
- 如果写 thread，每条 post 都必须推进论点
- 不要填充受众不需要的背景信息

### LinkedIn

- 只展开到让本领域之外的读者也能跟上
- 不要把它变成虚假的教训式 post，除非源素材本身确属反思性质
- 不要企业式励志节奏
- 不要堆砌赞美，不要"journey"式的填充内容

### 短视频

- 围绕视觉序列和证据点编写脚本
- 前几秒应展示结果、问题或冲击点
- 不要写出在纸面上比在屏幕上更顺耳的旁白

### YouTube

- 尽早展示结果或张力
- 按论点或递进组织，而不是填充式段落
- 仅在有助于清晰度时使用 chaptering

### Newsletter

- 以观点、冲突或成果开场
- 不要把第一段花在预热上
- 每个部分都需要增加新东西

## 二次分发流程

1. 选定锚定素材。
2. 提取 3 到 7 个原子化观点或场景。
3. 按犀利度、新颖性和证据性排序。
4. 为每个产出物分配一个强有力的想法。
5. 为每个平台适配结构。
6. 剔除平台式的填充内容。
7. 运行 quality gate。

## 交付物

当被要求做 campaign 时，返回：
- 如果 voice 匹配重要，附上简短的 voice profile
- 核心角度
- 平台原生草稿
- 仅在有助于执行时给出发布顺序
- 发布前必须填补的空缺

## Quality Gate

交付前：
- 每份草稿听起来像目标作者，而不是平台刻板印象
- 每份草稿都包含真实观点、证据点或具体观察
- 不残留通用的炒作语言
- 不残留虚假的互动诱饵
- 除非被要求，否则跨平台不重复文案
- 任何 CTA 都应是自然赢得且经用户批准的

## 相关 skill

- `brand-voice`：用于从源素材衍生的 voice profile
- `crosspost`：用于特定平台的分发
- `x-api`：用于获取近期 post 并发布经批准的 X 产出
