## 关键发现与建议

1. **缺失高度集中于 `hooks.json`（26/32）**：`hooks.json` 引用 27 个唯一 hook 脚本，zh-cn 仅有 `cost-tracker.js`，其余 26 个全缺——含 `plugin-hook-bootstrap.js` 与 `run-with-flags.js` 这两个所有 hook 运行所必需的入口/wrapper。

2. **`hooks.json` 脚本解析机制（影响评估）**：`hooks.json` 的 command 通过 `CLAUDE_PLUGIN_ROOT` 多路径探测解析脚本（内置 ~10 个候选回退：`~/.claude`、`plugins/ecc`、`plugins/cache/ecc/...` 等），**不相对 zh-cn 目录解析**。因此：
   - 若 zh-cn 与根仓库共用同一 ECC_ROOT（脚本在根存在），这些 hook 实际可运行 → 本轮"缺失"是**自包含性**缺失，不影响功能。
   - 若 zh-cn 作为**完全独立 plugin** 安装，26 个脚本缺失会导致全部 hook 失效 → 需补齐 `scripts/hooks/` 全量脚本。

3. **`utils.js` 与 `cost-tracker.js` 的直接 require 缺失（运行即抛错）**：与 hooks.json 不同，这俩是代码内 `require()`，相对模块解析基于自身位置，缺失会直接抛 `MODULE_NOT_FOUND`：
   - `utils.js` → `agent-data-home.js`
   - `cost-tracker.js` → `session-bridge.js`
   - **但**：第一轮已确认 `utils.js` 在所有引用点（`sessions.md`、`skill-health.md`、`hooks.json`）仅作 `existsSync` 探测哨兵、不被 `require` 执行；`cost-tracker.js` 仅作为 Stop hook 由 `run-with-flags.js` 包装调用（而该 wrapper 本身在第 2 项缺失）。故在 hooks.json 尚未实际运行前，这两个 require 不会触发。

4. **`typescript` skill 是真正的上游悬空引用（第 30 项）**：根 `skills/` 目录也不存在 `typescript` skill，与其余 3 个 skill（accessibility/docker-patterns/nextjs-turbopack，根均存在）不同。修复方式不是拷贝，而是：从根仓库补拷（若根有则同 29/31/32），或修订 [vue-patterns/SKILL.md:470](custom-install/zh-cn/skills/vue-patterns/SKILL.md#L470) 删除/改写该引用。本轮核实：根目录无此 skill，属后者。

5. **补齐建议（若追求自包含）**：优先级——
   - P0：`scripts/lib/agent-data-home.js`、`scripts/lib/session-bridge.js`（2 个直接 require 依赖，单文件，成本低）
   - P1：3 个 skill（accessibility、docker-patterns、nextjs-turbopack，根存在，单 SKILL.md 拷贝）
   - P2：26 个 hook 脚本（批量，但仅在 zh-cn 独立安装时必需；且这些脚本自身可能还有进一步的 `require` 链，会引发第三轮依赖）
   - 第 30 项 `typescript` skill：修订文档引用，而非拷贝。
