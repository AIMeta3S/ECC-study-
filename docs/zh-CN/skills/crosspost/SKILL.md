# Crosspost

在各平台分发内容，但不要把它变成披着四层外衣的同一个虚假帖子。

## 何时启用

- 用户希望在多个平台发布同一个核心想法
- 某次发布、更新、release 或文章需要平台专属版本
- 用户说 "crosspost"、"post this everywhere" 或 "adapt this for X and LinkedIn"

## 核心规则

1. 不要跨平台发布完全相同的文案。
2. 在各平台保持作者的声音。
3. 基于平台约束适配，而非基于刻板印象。
4. 一条帖子仍然只讲一件事。
5. 如果原文没有自然得出 CTA、提问或寓意，不要凭空捏造。

## 工作流

### Step 1：从主版本入手

首先挑选最强的源版本：
- 原始的 X 帖子
- 原始文章
- 发布说明
- thread
- 备忘录或 changelog

如果源内容仍需要声音塑造，先用 `content-engine`。

### Step 2：捕获声音指纹

如果当前 session 中尚未捕获源内容的声音，先运行 `brand-voice`。

直接复用生成的 `VOICE PROFILE`。
除非用户明确希望为本次活动重新覆盖，否则不要在这里再建一份临时声音清单。

### Step 3：按平台约束适配

### X

- 保持紧凑
- 以最尖锐的主张或成果开头
- 仅当单条帖子无法承载论证时才使用 thread
- 避免话题标签和空洞的填充内容

### LinkedIn

- 只添加面向该领域之外读者所需的上下文
- 不要把它变成虚假的创始人感悟帖
- 不要仅仅因为是 LinkedIn 就在结尾加上提问
- 如果作者本来就言辞犀利，不要强加打磨过的"专业语调"

### Threads

- 保持易读、直接
- 不要写虚假的超随意创作者文案
- 不要把 LinkedIn 版本粘贴过来再缩短

### Bluesky

- 保持简洁
- 保留作者的节奏
- 不要依赖话题标签或迎合信息流算法的措辞

## 发布顺序

默认顺序：
1. 先发布最强的原生版本
2. 为次要平台进行适配
3. 仅当用户希望得到排期帮助时才错开发布时间

除非确实有用，否则不要添加跨平台引用。大多数时候，帖子应当独立成立。

## 禁用模式

删除并重写以下任何内容：
- "Excited to share"
- "Here's what I learned"
- "What do you think?"
- "link in bio"（除非确实如此）
- 原文中没有的、泛泛的"专业感悟"段落

## 输出格式

返回：
- 主平台版本
- 每个所请求平台的适配版本
- 关于改动了什么以及为什么的简短说明
- 用户仍需解决的任何发布约束

## Quality Gate

发布前：
- 每个版本读起来都像是同一位作者在不同约束下写出的
- 没有任何平台版本显得臃肿或被磨平棱角
- 跨平台没有逐字重复的文案
- 为 LinkedIn 或 newsletter 使用而添加的任何额外上下文都是真正必要的

## 相关 skills

- `brand-voice`：用于可复用的、源自内容的声音捕获
- `content-engine`：用于声音捕获和源内容塑造
- `x-api`：用于 X 发布工作流
