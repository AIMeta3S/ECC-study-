# 前端设计方向

当工作不仅是让 UI 能运转，而是要让它显得有意图、打磨精致，并与产品领域相匹配时，使用本 skill。

来源：从 `linus707` 提交的停滞社区 PR #1659 中抢救整理而来。

注意：ECC 有意不重新打包 Anthropic 权威的 `frontend-design` skill。当你想要官方上游 skill 时，请从 `anthropics/skills` 安装。本 skill 是基于 #1659 中有用本地指导抢救整理而来的、ECC 专属的设计方向版本。

## 使用时机

- 用户要求构建网页、应用、dashboard、artifact、组件或 UI。
- 用户要求让界面更精致、更独特、更美观，或更少通用感。
- 实现需要在视觉层级、排版、色彩、动效、布局和交互方面做出抉择。
- 当前 UI 能用，但给人平淡、通用、模板化或与受众不匹配的感觉。

## 设计方向

在编码之前，选择一个具体方向：

1. 目的：这个界面承担什么工作？
2. 受众：谁会重复这一工作流，他们需要优先扫视什么？
3. 基调：实用、编辑式、俏皮、工业化、考究、技术化、极繁、极简、紧凑、冷静，或其他明确方向。
4. 记忆点：一个让成品显得刻意为之的设计想法。
5. 约束：框架、无障碍、性能、响应式以及现有 design system。

让方向与领域相匹配。SaaS 运维工具通常应当紧凑、安静、易于扫视。作品集、launch page、游戏或编辑类作品则可以更具表现力。不要把 landing page 的构图强加到一个需要每日重复使用的工具上。

## 实现指南

- 除非用户明确要求营销文案，否则将真实可用的体验作为首屏来构建。
- 在引入新的视觉系统之前，先使用项目现有的组件、tokens、图标库和路由模式。
- 当界面依赖图像、产品、地点、人物、游戏画面、图表或可检视的媒体时，使用真实或生成的视觉素材。
- 优先采用贴合语境的排版与间距，而非通用的超大 hero 文案。
- 让调色板保持多维：避免 UI 被单一色系主导。
- 使用 CSS variables 或现有的 design tokens，使设计方向在各状态下保持连贯。
- 明确设计响应式约束：网格、宽高比、最小/最大尺寸、稳定的工具栏，以及固定格式的控件，在标签或悬停状态出现时不应发生位移。
- 克制但有目的地使用动效。优先选择能清晰传达状态的高信号过渡效果，而非装饰性动画。
- 验证文本在移动端和桌面端的适配。长标签必须整洁地换行或调整大小，而不是溢出。

## 反模式

- 不要默认采用常见的生成式套路：紫色渐变、装饰性色块、超大卡片、空泛的 hero 文案，或类似图库素材的氛围式媒体。
- 不要在 UI 卡片内再嵌套卡片。
- 当领域需要克制时，不要在所有地方使用单一的装饰性风格。
- 不要把核心产品、工具、对象或工作流藏在通用的营销区块背后。
- 不要为了一个设计上的点缀而新增 dependency，除非它明显物有所值。
- 当控件自身足以说明问题时，不要在 UI 内描述 UI 的功能。

## 审查清单

- 首个视口立即传达产品、工作流或对象。
- 视觉层级支持扫视与重复使用。
- 排版贴合容器，且不与相邻内容重叠。
- 色彩选择具备对比度，且不会塌陷成单调的调色板。
- 在可用的情况下，使用图标来表示熟悉的工具操作。
- 响应式布局对看板、网格、工具栏、控件、磁贴和计数器具有稳定的尺寸。
- 素材正常渲染并承载主题，而不是充当填充物。
- 动效改善方位感，而不是掩盖卡顿。
- 除非有明确理由偏离，否则成品与仓库现有的前端约定保持一致。
