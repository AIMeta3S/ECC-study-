# ECC (Everything Claude Code) 初级使用指南

> 本文是 ECC 使用笔记，内容包括使用步骤、心得、经验、理解和思考等。
> 使用环境：macOS + claude code

ECC 是一个为 coding Agent 打造的插件系统，提供 Agent、Skill、Rules、Commands、Hooks 等组件，以便使用者更**便捷**、**精准**、**高效**的使用 coding Agent 进行编码任务。

## 安装方式的选择

官方提供的三种安装方式，都是全量安装，而 Agent、Skill、Commands 中有大量不常用的组件，并且安装的都是英文版本。为了适配团队的 开发模式、技术栈、任务特点和中文语境，我们采用**中文自定义安装**方式。具体步骤如下：
- 第一步：将仓库中的 Agents、Skills、Rules、Commands 目录下的文件（英文）全部翻译为中文。
- 第二步：根据团队的 开发模式、技术栈、任务特点等选择我们需要的 Agent、Skill、Rule、Command 文件，。

### 步骤 1：确认宿主环境

**为什么**：ECC 是插件，必须在宿主平台上运行。先确认你的宿主工具已安装且可用。

**Claude Code 用户：**

```bash
claude --version
```

你应该看到版本号 >= 2.1.0（例如 `2.1.x`）。

**其他宿主用户：** 确认你使用的工具已安装。支持的宿主包括：

| 宿主平台 | 支持状态 | 安装方式 |
|----------|---------|---------|
| Claude Code | 主要支持 | `/plugin install` |
| Cursor IDE | 完全支持 | `./install.sh --target cursor` |
| OpenCode | 完全支持 | `npm install ecc-universal` |
| Codex (App + CLI) | 完全支持 | 自动检测或 `scripts/sync-ecc-to-codex.sh` |
| Gemini CLI | 实验性 | 项目本地 `.gemini/GEMINI.md` |
| Zed | 支持 | `./install.sh --profile minimal --target zed` |
| GitHub Copilot | 支持（仅规则层） | 自动检测 `.github/copilot-instructions.md` |

### 步骤 2：安装插件（推荐方式）

**为什么**：插件方式最简单，一条命令即可注入 Skills、Commands、Agents 和 Hooks，无需手动复制文件。

在 Claude Code 会话中执行：

```
/plugin marketplace add https://github.com/affaan-m/ECC

/plugin install ecc@ecc
```

你应该看到安装成功的确认信息。

**验证安装：**

```
/plugin list ecc@ecc
```

你应该看到 ECC 的 Skills、Commands 和 Agents 列表。

> **注意：** 三个标识符不要混淆：
> - GitHub 仓库：`affaan-m/ECC`
> - 插件标识符：`ecc@ecc`（用于 `/plugin install`）
> - npm 包名：`ecc-universal`（用于 `npm install`）

### 步骤 3：安装规则（必须手动步骤）

**为什么**：Claude Code 的插件系统有一个已知限制——**插件不能自动分发 `rules`**。Rules 是 ECC 的核心组成部分（编码风格、安全检查、Git 工作流等），必须手动复制。

```bash
# 创建规则目录
mkdir -p ~/.claude/rules/ecc
```

```bash
# 克隆仓库到本地
git clone https://github.com/affaan-m/ECC.git
cd ECC

# 复制通用规则（必选）
cp -R rules/common ~/.claude/rules/ecc/

# 复制你使用的语言规则（按需选一个或多个）
cp -R rules/typescript ~/.claude/rules/ecc/    # TypeScript/JavaScript
# cp -R rules/python ~/.claude/rules/ecc/      # Python
# cp -R rules/golang ~/.claude/rules/ecc/      # Go
# cp -R rules/java ~/.claude/rules/ecc/        # Java
# cp -R rules/rust ~/.claude/rules/ecc/        # Rust
```

**可用的语言规则目录：**

`common`（通用）、`typescript`、`python`、`golang`、`java`、`kotlin`、`swift`、`rust`、`php`、`cpp`、`csharp`、`perl`、`ruby`、`dart`、`fsharp`、`angular`、`arkts`、`web`、`zh`（中文）

> **重要：** 复制整个语言目录（如 `rules/common`），不要只复制里面的文件。这样相对引用才能正常工作，文件名也不会冲突。

**验证规则安装：**

```bash
ls ~/.claude/rules/ecc/
```

你应该看到：
```
common    typescript
```
（或你复制的其他语言目录）

> **警告：不要叠加安装！** 如果已经通过 `/plugin install` 安装了插件，就不要再运行 `./install.sh --profile full` 或 `npx ecc-install --profile full`。叠加安装会导致 Skills 和 Hooks 重复，产生异常行为。

### 步骤 4：第一个 Skill 体验

**目标**：体验 ECC 最实用的 Skill 之一——`search-first`（编码前先搜索已有方案）。

在 Claude Code 会话中，描述一个功能需求，例如：

```
我要给项目添加一个 HTTP 客户端，支持重试和超时处理
```

ECC 的 `search-first` Skill 会自动介入（当你提出的功能需求很可能已有现成方案时），或手动提及 `/search-first`。

**你应该看到**：Claude Code 会先搜索 npm、PyPI、GitHub 等渠道，评估现有方案，然后给出建议：

1. **搜索阶段**：Agent 在多个渠道并行搜索（npm/PyPI、MCP 服务器、GitHub、Web）
2. **评估阶段**：对候选方案打分（功能性、维护状态、社区活跃度、文档质量、许可证）
3. **决策阶段**：给出最终建议——直接采用（Adopt）、扩展封装（Extend）或自行构建（Build）

**刚刚发生了什么**：

1. `search-first` Skill 被 Claude Code 自动发现和加载（因为插件已安装）
2. Skill 触发后，Agent 启动了研究员（researcher）工作流，在多个渠道并行搜索
3. Agent 对搜索结果进行了评分和排序，最终给出了带理由的推荐
4. 你得到了一个经过调研的建议，而不是从零开始写代码

## 常见问题

### Q: 安装后出现 "Duplicate hooks file detected" 错误

**原因**：ECC 的 `hooks/hooks.json` 被 Claude Code v2.1+ 自动加载，但某个配置文件中又手动声明了 hooks，导致重复。

**A**: 不要在 `plugin.json` 中添加 `"hooks"` 字段。Claude Code v2.1+ 会按约定自动加载插件目录下的 `hooks/hooks.json`，手动声明会触发重复检测错误。

```bash
# 检查是否有重复的 hooks 声明
cat .claude-plugin/plugin.json
# 确认其中没有 "hooks" 字段
```

### Q: 上下文窗口变小了 / Claude 提示上下文不足

**原因**：启用了过多的 MCP 服务器。每个 MCP 工具描述都会消耗 token，可能将 200k 上下文窗口压缩到约 70k。

**A**: 精简 MCP 配置：

```bash
# 在 Claude Code 中用 /mcp 命令管理 MCP 服务器
# 保持启用的 MCP 不超过 10 个，活跃工具不超过 80 个

# 或降低 SessionStart 附加上下文
export ECC_SESSION_START_MAX_CHARS=4000

# 订阅用户可关闭费用估算警告
export ECC_CONTEXT_MONITOR_COST_WARNINGS=off
```

### Q: 我只想用 ECC 的部分组件（比如只要 Agents）

**原因**：ECC 的组件是独立的，不需要全部安装。

**A**: 使用手动安装方式，只复制你需要的部分：

```bash
git clone https://github.com/affaan-m/ECC.git
cd ECC

# 只要 Agents
cp agents/*.md ~/.claude/agents/

# 只要 Rules
mkdir -p ~/.claude/rules/ecc/
cp -r rules/common ~/.claude/rules/ecc/

# 只要某个特定 Skill
mkdir -p ~/.claude/skills/ecc
cp -r skills/search-first ~/.claude/skills/ecc/
```

### Q: 我不小心叠加了多种安装方式，现在行为异常

**原因**：同时使用了 `/plugin install` 和 `./install.sh --profile full`，导致 Skills 和 Hooks 重复。

**A**: 按顺序清理：

```bash
# 1. 移除 Claude Code 插件
# 在 Claude Code 中移除 ecc@ecc 插件

# 2. 从仓库运行卸载脚本
git clone https://github.com/affaan-m/ECC.git
cd ECC
npm install
node scripts/uninstall.js --dry-run   # 先预览将删除的文件
node scripts/uninstall.js             # 确认后执行删除

# 3. 删除手动复制的规则目录
rm -rf ~/.claude/rules/ecc/

# 4. 选择一种方式重新安装
```

也可以使用生命周期管理命令：

```bash
node scripts/ecc.js list-installed    # 查看已安装的文件
node scripts/ecc.js doctor            # 诊断问题
node scripts/ecc.js repair            # 尝试修复
```

## 替代安装方式

### 手动安装（完全控制）

适合不想使用插件方式、或需要精细控制安装组件的用户。

```bash
git clone https://github.com/affaan-m/ECC.git
cd ECC
npm install

# 使用安装脚本，--profile full 安装所有组件
./install.sh --profile full

# 或者只要核心组件，不要 hooks
./install.sh --profile core --without baseline:hooks
```

> **注意：** 选择手动安装后，不要再执行 `/plugin install`。

### npm 安装（面向 OpenCode 或编程集成）

```bash
npm install ecc-universal
```

对于 OpenCode 用户，在 `opencode.json` 中添加：

```json
{
  "plugin": ["ecc-universal"]
}
```

### 不确定装什么？先用顾问

如果你不确定需要哪个 Profile 或组件，先用顾问工具查询：

```bash
npx ecc consult "安全审查" --target claude
```

它会返回匹配的组件、相关的 Profile 以及预览/安装命令。

## 卸载/重置方法

### 插件方式卸载

1. 在 Claude Code 中移除 ecc@ecc 插件
2. 删除手动复制的规则目录：

```bash
rm -rf ~/.claude/rules/ecc/
```

### 手动安装方式卸载

```bash
cd ECC  # 进入仓库目录
node scripts/uninstall.js --dry-run   # 预览将删除的内容
node scripts/uninstall.js             # 执行卸载
```

ECC 只会删除它记录在安装状态中的文件，不会删除不相关的文件。

### 低上下文 / 无 Hooks 安装

如果你只需要 Rules、Agents、Commands 和核心 Skills，不需要 Hooks：

```bash
./install.sh --profile minimal --target claude
```
