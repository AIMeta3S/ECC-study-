# 保存会话命令

记录本会话中发生的一切——构建了什么、哪些成功了、哪些失败了、还有哪些未完成——并将其写入一个带日期的文件，让下一次会话能精确地接着当前进度继续。

## 何时使用

- 结束工作会话、即将关闭 Claude Code 之前
- 即将触及上下文限制时（先执行此命令，然后开始一个新会话）
- 解决了某个想记住的复杂问题之后
- 任何时候需要将上下文交接给未来的会话

## 流程

### Step 1：收集 context

在写文件之前，收集以下内容：

- 阅读本会话中修改过的所有文件（使用 git diff 或从对话中回忆）
- 审查讨论过、尝试过和决定过的事项
- 记下遇到的任何错误以及如何解决的（或未解决的）
- 如有需要，请检查当前的 test/build 状态

### Step 2：如果 session-data 文件夹不存在则创建它

在用户的 Claude 主目录下创建规范的 session-data 文件夹：

```bash
mkdir -p ~/.claude/session-data
```

### Step 3：写入 session 文件

创建 `~/.claude/session-data/YYYY-MM-DD-<short-id>-session.tmp`，使用当天的实际日期以及一个满足 `session-manager.js` 中 `SESSION_FILENAME_REGEX` 规则的 short-id：

- 允许的字符：字母 `a-z` / `A-Z`、数字 `0-9`、连字符 `-`、下划线 `_`
- 最小长度要求：1 个字符
- 对新文件的推荐风格：小写字母、数字和连字符，长度不少于 8 个字符以避免冲突

有效示例：`abc123de`、`a1b2c3d4`、`frontend-worktree-1`、`ChezMoi_2`
新文件应避免使用：`A`、`test_id1`、`ABC123de`

完整的有效文件名示例：`2024-01-15-abc123de-session.tmp`

旧版文件名 `YYYY-MM-DD-session.tmp` 仍然有效，但新的会话文件应优先采用 short-id 形式，以避免同一天内的冲突。

### Step 4：用以下所有章节填充文件

请务必如实填写每个部分。不要跳过任何部分——如果某个部分确实没有内容，请填写“暂无”或“不适用”。不完整的文件比一个诚实的空白部分更糟糕。

### 第 5 步：将文件展示给用户

写入完成后，显示文件的全部内容并询问：

```
会话已保存到 [会话文件的实际解析路径]

请确认会话内容是否准确，在我们结束前有什么需要更正或补充的吗？
```

等待确认。如有需要，进行修改。

## 我们正在构建的内容

为 Next.js 应用构建用户认证系统。用户使用邮箱/密码注册，接收一个存储在 httpOnly cookie（而非 localStorage）中的 JWT，受保护的路由通过中间件检查有效令牌。目标是实现浏览器刷新后的会话持久化，同时避免向 JavaScript 暴露令牌。

---

## 已确认有效的部分（附带证据）

- **`/api/auth/register` 端点** — 已通过以下方式证实：Postman POST 返回 200 并附带用户对象，Supabase 仪表板中可见行，bcrypt 哈希正确存储
- **`lib/auth.ts` 中的 JWT 生成** — 已通过以下方式证实：单元测试通过（`npm test -- auth.test.ts`），在 jwt.io 解码令牌显示正确载荷
- **密码哈希** — 已通过以下方式证实：`bcrypt.compare()` 在测试中返回 true

---

## 未能成功的内容（及原因）

- **Next-Auth 库** — 失败，原因：与我们自定义的 Prisma 适配器冲突，每次请求都抛出“无法在此配置中使用凭证提供程序与适配器”。不值得调试——对我们的设置来说过于固执己见。
- **将 JWT 存储在 localStorage 中** — 失败，原因：SSR 渲染发生在 localStorage 可用之前，导致每次页面加载时出现 React hydration 不匹配错误。此方法从根本上与 Next.js SSR 不兼容。

---

## 尚未尝试的部分

- 将 JWT 作为 httpOnly cookie 在登录路由的响应中设置（最可能的解决方案）
- 使用 `next/headers` 中的 `cookies()` 在服务器组件中读取令牌
- 编写 middleware.ts 通过检查 cookie 存在与否来保护路由

## 注意事项

- 每次会话使用独立的文件——切勿追加到之前会话的文件中
- “未能成功的内容”部分是最关键的——没有它，未来的会话很可能会盲目重试已失败的方法
- 如果用户要求在会话中途保存（而非仅在结束时），则保存当前已知的内容，并明确标注正在进行中的条目
- 该文件旨在由 Claude 在下次会话开始时通过 `/resume-session` 读取。
- 使用规范的全局会话存储路径：`~/.claude/session-data/`
- 新会话文件应优先采用 short-id 文件名形式（`YYYY-MM-DD-<short-id>-session.tmp`）
