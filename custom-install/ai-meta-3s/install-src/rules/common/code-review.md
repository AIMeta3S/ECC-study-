# 代码审查标准

## 目的

代码审查在代码 merge 前确保质量、安全和可维护性。本规则定义了何时以及如何进行代码审查。

## 何时审查

**强制性审查触发条件：**

- 编写或修改代码后
- 向共享分支 commit 前
- 当修改了 security-sensitive 代码（如认证、支付、用户数据等）时
- 进行架构变更时
- 合并 Pull Request 之前

**审查前要求：**

请求审查前，确保：

- 所有自动化检查（CI/CD）均已通过
- 合并冲突已解决
- 分支已与目标分支同步

## 审查清单

标记代码完成前：

- [ ] 代码可读性好，命名规范。
- [ ] function 聚焦（<50 行）
- [ ] file 内聚（<800 行）
- [ ] 无过深嵌套（>4 层）
- [ ] 错误已显式处理
- [ ] 没有硬编码的密钥或凭证
- [ ] 无 console.log 或 debug 语句
- [ ] 新功能已有测试
- [ ] 测试覆盖率至少达到 80%。

## 安全审查触发条件

**遇到以下情况时，停止并使用 security-reviewer agent：**

- 认证或授权代码
- 用户输入处理
- 数据库查询
- 文件系统操作
- 外部 API 调用
- 加解密操作
- 支付或财务代码

## 审查严重程度等级

| 等级 | 含义 | 动作 |
|------|------|------|
| 致命 | 安全漏洞或数据丢失风险 | **阻断** - 合并前必须修复 |
| 高 | 缺陷或严重质量问题 | **警告** - 合并前应当修复 |
| 中 | 可维护性关注点 | **提示** - 建议修复 |
| 低 | 风格或次要建议 | **备注** - 可选 |


## Agent 使用

请使用以下 agent 进行代码审查：

| Agent | 用途 |
|-------|------|
| **code-reviewer** | 通用代码质量、设计模式、最佳实践 |
| **security-reviewer** | 安全漏洞、OWASP Top 10 |
| **typescript-reviewer** | TypeScript/JavaScript 相关问题 |
| **vue-reviewer** | Vue.js 相关问题 |
| **python-reviewer** | Python 相关问题 |
| **fastapi-reviewer** | FastAPI 相关问题 |

## 审查工作流

```
1. 运行 git diff 以了解变更
2. 首先检查安全清单
3. 审查代码质量清单
4. 运行相关测试
5. 验证覆盖率 >= 80%
6. 使用合适的 agent 进行详细审查
```

## 常见问题及应对措施

### 安全

- 硬编码凭证（API 密钥、密码、令牌）
- SQL 注入（查询中的字符串拼接）
- XSS 漏洞（未转义的用户输入）
- 路径遍历（未清理的文件路径）
- 缺少 CSRF 防护
- 身份验证绕过

### 代码质量

- 函数过长（超过50行）——拆分为更小的函数
- 文件过大（超过800行）——提取模块
- 嵌套过深（超过4层）——使用提前返回
- 缺少错误处理——需要显式处理
- Mutation patterns——优先使用不可变操作
- 缺少测试——增加测试覆盖

### 性能

- N+1 查询——使用 JOIN 或批处理
- 缺少分页——在查询中添加 LIMIT
- 无限制查询——添加约束
- 缺少缓存——缓存高开销操作

## 批准标准

- **Approve**: 无致命或高风险问题
- **Warning**: 仅限高优先级问题（谨慎合并）
- **Block**: 发现致命问题
