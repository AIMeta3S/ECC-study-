# Blender 运动状态检查

## 何时使用

- 一个 Blender 角色在动画中看起来扭曲、镜像翻转、压扁、偏移或脚部滑动。
- 用户询问导入的 avatar、骨架或重定向后的动作是否与预期姿势匹配。
- 你需要将渲染证据与结构化事实（如骨骼、包围盒、接触点和朝向向量）进行比较。
- 某个工作流取决于判断某个模型是角色、道具、代理网格、控制 rig，还是失败的导入。

## 核心原则

不要仅凭截图评判动画 3D 资产。截图是审查证据，但它们隐藏了轴向约定、骨骼名称、物体缩放、局部变换、父级网格、材质槽和逐帧接触状态。

先提取结构化的 Blender 状态，再用视口截图或渲染结果来确认这些事实所暗示的内容。

## 工作原理

1. 在评判动作之前，先建立干净的场景和资产基线。
2. 使用导出器或在 Blender 自身的解释器内运行的 Blender Python，从 Blender 中提取结构化事实。
3. 采样最有可能暴露接触、朝向、缩放和重定向错误的帧。
4. 将测量得到的事实与用户预期的姿势、方向、地平面和渲染目标进行比较。
5. 返回一份简洁的报告，区分已确认的事实、可能的原因和必需的修复。

## 检查工作流

1. 盘点场景。
   - 列出网格、骨架、空物体、相机、灯光、修改器、父级关系和隐藏物体。
   - 在评判 avatar 之前，将角色网格与辅助/代理几何体分开。
   - 记录物体空间和世界空间的包围盒。

2. 识别骨骼结构。
   - 捕获骨架名称、姿势骨骼、骨骼 head/tail、roll、父级链、约束和静息姿势轴向。
   - 映射语义骨骼，如髋部、脊柱、颈部、头部、肩部、肘部、手部、大腿、膝盖、脚踝和脚部。
   - 标记缺失的左右配对和不寻常的命名方案。

3. 确定前向、上向和侧向轴。
   - 同时使用骨盆、脊柱、肩部、髋部、头部和脚部；不要依赖单一的网格法线。
   - 比较局部骨架轴向与世界轴向，以及导入文件的约定，例如 glTF 的 Y-up 与 Blender 的 Z-up。
   - 当面部/头部/脚部方向与根运动冲突时，标记为可能的镜像或反向导入。

4. 采样动画帧。
   - 检查首帧、中间帧、接触帧、腾空帧和极限帧。
   - 记录根位置、根朝向、骨盆高度、躯干倾斜、肢体方向、脚部离地间隙和网格边界。
   - 对于长动作或快速动作，在翻转、落地、转弯、碰撞和地面接触附近更密集地采样。

5. 在归咎于重定向之前检查模型完整性。
   - 在应用动画之前，确认干净的基线形状。
   - 除非用户明确要求修复，否则保留原始网格、材质、骨架和蒙皮。
   - 在证明并非如此之前，将无法解释的类球体块、巨大的代理网格或挤压变形的身体视为导入/选择问题。

6. 诊断接触和动作问题。
   - 地面穿透：逐帧比较最低的脚部或鞋部顶点与地板高度。
   - 脚部滑动：比较踩地帧之间的脚部世界位置。
   - 腿部交叉：比较左/右大腿、膝盖、脚踝和脚部的侧边顺序。
   - 扭转损伤：将骨骼的 swing 方向与围绕肢体轴的 roll/twist 分开比较。
   - 缩放漂移：将动画网格边界与干净基线边界进行比较。

7. 在给出观点之前先报告事实。
   - 包含帧编号、物体名称、骨骼名称、世界坐标和阈值。
   - 将已确认的失败与视觉上的怀疑分开。
   - 仅在结构化状态解释了需要查看什么之后，才附加截图。

## 示例

### 带有脚部滑动的步行循环

场景：一个重定向的角色在步行循环中看起来像在滑冰，但正面相机角度使得脚部接触难以判断。

应用工作流：
- 盘点场景：角色网格 `HeroBody`、骨架 `HeroRig`、地平面 `Floor`，没有隐藏的代理网格。
- 识别骨骼结构：语义脚部是 `foot.L` 和 `foot.R`；髋部是 `pelvis`；根骨骼是 `root`。
- 采样动画帧：检查踩地脚时刻附近的第 1、18、24、30、42 和 48 帧。
- 诊断接触和动作问题：比较踩地帧期间的世界空间脚部位置。

提取的事实：

| 帧 | 事实 | 证据 |
| --- | --- | --- |
| 18 | 左脚踩地 | `foot.L min_z = 0.004`，脚趾和脚跟都接近地板 |
| 24 | 左脚在踩地时滑动 | `foot.L x = 0.21 -> 0.28`，跨越六帧 |
| 30 | 骨盆持续向前移动 | `pelvis y = 1.14 -> 1.31` |

结论：渲染就绪状态为失败。动作需要脚部锁定清理或重定向约束审查；身体网格不需要比例修改。

### 反向导入的角色

场景：一个角色在静帧中看起来正确，但动画朝预期行进方向的反方向移动。

应用工作流：
- 确定前向、上向和侧向轴：比较头部、胸部、脚部和根运动。
- 采样动画帧：检查第 1 帧和行进路径的中点。
- 在给出观点之前先报告事实：分别包含根朝向和模型朝向方向。

提取的事实：

| 帧 | 事实 | 证据 |
| --- | --- | --- |
| 1 | 角色面部朝向世界 `-Y` | 从 `neck` 到 `head` 的向量（代表头部/胸部朝向）解析为 `-Y` |
| 72 | 根运动朝世界 `+Y` 方向行进 | `root y = 0.0 -> 2.8` |
| 72 | 脚部在视觉上仍朝前行，与行进方向相反 | 脚趾骨骼指向 `-Y` 而位移为 `+Y` |

结论：可能是反向导入或重定向的前向轴不匹配。在编辑动画曲线之前，先修复导入/重定向的轴向映射。

## 实用阈值

- 除非场景单位缩放另有说明，否则假设使用 Blender 默认的米制单位。
- 除非地板是软的或刻意风格化，否则将 1-2 cm 以上的地面穿透视为可见。
- 将 5% 以上的突然缩放变化视为可能的 rig、约束或变换继承问题。
- 即使后来恢复，也将腾空倒置动作期间左/右脚踝侧边顺序翻转视为腿部交叉风险。
- 除非源动作包含急转弯，否则将每帧 30 度以上的根朝向跳变视为可疑。

## 反模式

- 除非任务明确是网格修复，否则不要修改身体比例来强行匹配姿势。
- 不要在记录干净的基线之前就烘焙掉它。
- 不要用一个渲染的相机角度作为姿势正确的证明。
- 在记录为什么辅助物体不属于角色的一部分之前，不要删除它们。
- 不要在没有同时检查头部、脚部、躯干和根运动的情况下，假设 avatar 朝向 +Y、-Y、+X 或 -X。

## 工具说明

如果有可用的 Blender 状态导出器，优先使用包含网格、骨架、姿势骨骼、材质、接触点、包围盒和采样动画帧的 JSON。如果没有导出器，则通过 Blender 本身运行一个小型的 Blender Python 脚本，例如 `blender --background scene.blend --python collect_motion_state.py`，因为 `bpy` 在普通的系统 Python 解释器中不可用。
