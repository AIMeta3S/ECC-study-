# Frontend Slides

创建零依赖、动画丰富、完全在浏览器中运行的 HTML 演示文稿。

灵感来源于 zarazhangrui 作品中展示的视觉探索方法（致谢：@zarazhangrui）。

## 何时激活

- 创建演讲幻灯片、路演幻灯片、工作坊幻灯片或内部演示文稿
- 将 `.ppt` 或 `.pptx` 幻灯片转换为 HTML 演示文稿
- 改进现有 HTML 演示文稿的布局、动效或排版
- 与尚未明确设计偏好的用户一起探索演示风格

## 不可妥协的要求

1. **零依赖**：默认使用单个自包含的 HTML 文件，内联 CSS 和 JS。
2. **必须适配视口**：每张幻灯片必须完整放入一个视口内，内部不得出现滚动。
3. **展示而非描述**：使用视觉预览代替抽象的风格问卷。
4. **独特设计**：避免千篇一律的紫色渐变、白底 Inter 字体、模板化的幻灯片。
5. **生产级质量**：保持代码有注释、可访问、响应式且性能良好。

生成前，阅读 `STYLE_PRESETS.md`，了解适配视口的 CSS 基础、密度限制、预设目录和 CSS 注意事项。

## 工作流程

### 1. 判定模式

选择一条路径：
- **新建演示文稿**：用户有主题、笔记或完整草稿
- **PPT 转换**：用户有 `.ppt` 或 `.pptx` 文件
- **增强改进**：用户已有 HTML 幻灯片并希望进行改进

### 2. 挖掘内容

只询问最低限度的必要信息：
- purpose：路演、教学、会议演讲、内部汇报
- length：短（5-10 张）、中（10-20 张）、长（20 张以上）
- content state：成稿、粗略笔记、仅有主题

如果用户已有内容，请要求他们在确定风格前先粘贴内容。

### 3. 挖掘风格

默认采用视觉探索方式。

如果用户已经知道想要的预设，跳过预览直接使用。

否则：
1. 询问整套幻灯片应营造何种感受：惊艳、充满活力、专注、受到启发。
2. 在 `.ecc-design/slide-previews/` 中生成 **3 个单张幻灯片预览文件**。
3. 每个预览必须自包含、清晰展示排版/颜色/动效，并控制在约 100 行幻灯片内容以内。
4. 询问用户保留哪个预览，或希望混合其中哪些元素。

在将氛围映射到风格时，参考 `STYLE_PRESETS.md` 中的预设指南。

### 4. 构建演示文稿

输出以下任一：
- `presentation.html`
- `[presentation-name].html`

仅当整套幻灯片包含提取的或用户提供的图片时，才使用 `assets/` 文件夹。

必需的结构：
- 语义化的幻灯片区块
- 来自 `STYLE_PRESETS.md` 的适配视口的 CSS 基础
- 使用 CSS custom properties 存放主题值
- 一个用于键盘、滚轮和触摸导航的演示控制器类
- 使用 Intersection Observer 触发显示动画
- 支持 reduced-motion

### 5. 强制适配视口

将其视为硬性门槛。

规则：
- 每个 `.slide` 必须使用 `height: 100vh; height: 100dvh; overflow: hidden;`
- 所有文字和间距必须使用 `clamp()` 进行缩放
- 当内容放不下时，拆分为多张幻灯片
- 不得通过将文字缩小到难以阅读的尺寸来解决溢出
- 不得在幻灯片内部出现滚动条

使用 `STYLE_PRESETS.md` 中的密度限制和强制性 CSS 代码块。

### 6. 校验

在这些尺寸下检查完成的幻灯片：
- 1920x1080
- 1280x720
- 768x1024
- 375x667
- 667x375

如果可以使用浏览器自动化，用它验证没有幻灯片溢出且键盘导航正常工作。

### 7. 交付

交付时：
- 除非用户希望保留，否则删除临时预览文件
- 在有用时使用平台合适的打开方式打开幻灯片
- 汇总文件路径、使用的预设、幻灯片数量和便捷的主题自定义点

对当前操作系统使用正确的打开命令：
- macOS：`open file.html`
- Linux：`xdg-open file.html`
- Windows：`start "" file.html`

## PPT / PPTX 转换

进行 PowerPoint 转换时：
1. 优先使用 `python3` 配合 `python-pptx` 提取文本、图片和备注。
2. 如果 `python-pptx` 不可用，询问是安装它还是退回到基于手动/导出的工作流。
3. 保留幻灯片顺序、演讲者备注和提取的资源。
4. 提取完成后，运行与新建演示文稿相同的风格选择工作流。

保持转换过程的跨平台性。当 Python 能完成任务时，不要依赖仅限 macOS 的工具。

## 实现要求

### HTML / CSS

- 除非用户明确希望使用多文件项目，否则使用内联 CSS 和 JS。
- 字体可来自 Google Fonts 或 Fontshare。
- 优先采用有氛围感的背景、强烈的字体层级和清晰的视觉方向。
- 使用抽象形状、渐变、网格、噪点和几何图形，而非插画。

### JavaScript

需包含：
- 键盘导航
- 触摸/滑动导航
- 鼠标滚轮导航
- 进度指示器或幻灯片序号
- 进入时触发的显示动画触发器

### 可访问性

- 使用语义化结构（`main`、`section`、`nav`）
- 保持对比度可读
- 支持纯键盘导航
- 遵循 `prefers-reduced-motion`

## 内容密度限制

除非用户明确要求更密集的幻灯片且仍保持可读性，否则使用以下上限：

| 幻灯片类型 | 上限 |
|------------|-------|
| 标题页 | 1 个标题 + 1 个副标题 + 可选标语 |
| 内容页 | 1 个标题 + 4-6 个项目符号 或 2 段短段落 |
| 特性网格 | 最多 6 张卡片 |
| 代码页 | 最多 8-10 行 |
| 引用页 | 1 段引文 + 出处 |
| 图片页 | 1 张受视口约束的图片 |

## 反模式

- 没有视觉辨识度的通用创业公司风格渐变
- 使用系统字体的幻灯片，除非有意追求编辑风格
- 冗长的项目符号堆砌
- 需要滚动的代码块
- 在短屏幕上会破裂的固定高度内容框
- 无效的取反 CSS 函数，如 `-clamp(...)`

## 交付检查清单

- 演示文稿可在浏览器中通过本地文件运行
- 每张幻灯片都适配视口，无需滚动
- 风格独特且有明确意图
- 动画有意义，不杂乱
- 遵循 reduced-motion
- 交付时解释了文件路径和自定义点
