# Manim 视频

当动作、结构和清晰度比照片级真实感更重要时，使用 Manim 制作技术解释动画。

## 何时激活

- 用户需要技术解释动画
- 概念是一张图表、工作流、架构、指标演进或系统图
- 用户需要面向 X 或落地页的简短产品或发布演示
- 视觉效果应当精确而非泛泛的电影感

## 工具要求

- `manim` CLI 用于场景渲染
- `ffmpeg` 用于必要的后期处理
- `video-editing` 用于最终合成或精修
- `remotion-video-creation` 当最终成片需要合成 UI、字幕或额外动画层时使用

## 默认输出

- 短篇 16:9 MP4
- 一张缩略图或封面帧
- 分镜脚本加上场景规划

## 工作流

1. 用一句话定义核心视觉主旨。
2. 将概念拆分为 3 到 6 个场景。
3. 确定每个场景要证明什么。
4. 在编写 Manim 代码之前先写场景大纲。
5. 先渲染最小可用版本。
6. 渲染通过后再精修排版、间距、配色和节奏。
7. 仅在能带来增益时才交接给更广泛的视频工具链。

## 场景规划规则

- 每个场景只证明一件事
- 避免图示信息过载
- 优先使用渐进式揭示而非全屏堆砌
- 用动作来解释状态变化，而不是单纯让屏幕热闹
- 标题卡应简短且信息密度高

## 网络图默认配置

针对社交图谱和网络优化类解释动画：

- 先展示当前图谱，再展示优化后的图谱
- 区分低信号的冗余关注与高信号的桥接节点
- 高亮活跃路径节点和目标聚类
- 如有必要，添加一个最终场景展示为该 skill 提供依据的自我改进脉络

## 渲染约定

- 默认 16:9 横屏，除非用户要求竖屏
- 先进行低画质的冒烟测试渲染
- 仅在构图和时序稳定后再提升画质
- 导出一帧干净的缩略图，在社交媒体尺寸下依然清晰可读

## 可复用起点

使用 [assets/network_graph_scene.py](assets/network_graph_scene.py) 作为网络图解释动画的起点。

冒烟测试示例：

```bash
manim -ql assets/network_graph_scene.py NetworkGraphExplainer
```

## 输出格式

返回：

- 核心视觉主旨
- 分镜脚本
- 场景大纲
- 渲染计划
- 任何后续的精修建议

## 相关 Skills

- `video-editing` 用于最终精修
- `remotion-video-creation` 用于动画密集的后期处理或合成
- `content-engine` 当动画是更大规模发布的一部分时使用
