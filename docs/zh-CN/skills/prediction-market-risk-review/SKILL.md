# 预测市场风险审查

在任何 prediction-market 工作流触及用户金融上下文、venue 认证、投资组合数据、自动化或具备执行能力的工具之前，使用此 skill。

## 审查关卡

### 建议边界

- 确认输出仅为信息性内容。
- 移除买入/卖出/持有/仓位大小的建议。
- 保持用户手动决策点明确。

### venue 与监管边界

- 识别 venue 条款、地域限制、账户限额和 API 规则。
- 当相关时，将押注、衍生品、证券或商品的定性模糊之处标记以供法律审查。
- 不要绕过 venue 限制或速率限制。

### 数据质量

- 检查市场流动性、点差、结算规则、过期价格和来源时间戳。
- 将公开的 venue 数据与 Itô 受限数据分开。
- 不要在无标签的情况下混合公开与私有来源。

### 安全性

- 不要请求或存储私钥、助记词或密码。
- 不要将 `ITO_API_KEY` 和 venue API key 写入日志或文档。
- 默认使用只读 scope。
- 在任何私有实现添加执行能力之前，要求具备熔断器、支出限额、dry run 和人工批准。

### 隐私

- 最小化用户投资组合、金融和知识库数据。
- 在公开 artifact 中对私有来源进行脱敏。
- 仅保留审查所需的字段。

## 输出契约

返回：

1. 已审查范围
2. pass/warn/fail 发现
3. 被阻止的操作
4. 必需的缓解措施
5. 安全的下一步

如果请求了任何具备执行能力的步骤，要求单独的实施计划和明确的用户批准。
